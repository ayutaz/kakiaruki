# 目的・範囲・境界

更新日: 2026-09-14

## 1. 目的

本プロジェクトの目的は、次の体験をブラウザ上で成立させることです。

1. プレイヤーが一筆で生物の骨格を描く。
2. 描線を、物理Bodyと関節から成る生物へ変換する。
3. 同じ形の複数個体に異なる動作パラメータを与える。
4. 数秒間の物理シミュレーションで移動能力を評価する。
5. 選択・交叉・突然変異で次世代を作る。
6. 世代を重ねると、歩く・跳ねる・転がるなどの動きが現れる。
7. 良い個体の動きをリプレイし、形の描き直しへ戻れる。

本質は「形をAIが生成すること」ではありません。プレイヤーが形を決め、進化計算は **関節の動かし方**を探索します。

## 2. MVPの範囲

### 含める

- デスクトップのChromium系ブラウザを最初の対象とする。
- マウス／ペン相当のPointer入力で一筆を記録する。
- 描線を有限個のNodeとEdgeへ変換する。
- 各Edgeをカプセル状の剛体にし、共有Nodeを回転関節として接続する。
- 固定タイムステップで複数個体を評価する。
- 周期関数ベースの関節コントローラを遺伝子にする。
- 前方移動を主目的とするFitnessを用いる。
- 個体数、表示個体数、学習速度を調整できるようにする。
- ベスト個体のリプレイと、形の描き直しを行えるようにする。
- 乱数Seedと主要パラメータを記録し、同一環境で再試行可能にする。

### 最初のMVPから外す

- ニューラルネットワーク、強化学習、Pythonサーバー。
- 形態そのものの自動進化。
- アカウント、クラウド保存、オンラインランキング。
- 原作と同一の名称、UI、アート、音、文章、ランキングSDK。
- スマートフォンの性能保証。
- Web Workerによる並列シミュレーション。
- 任意の自己交差、極端に複雑な閉ループの完全対応。

このうち「Web Workerによる並列シミュレーション」は引き続き対象外です。学習中の停止は、1世代ずつフレームに分けることで緩和しました（[D-011](09-risks-open-questions-and-decisions.md)）。

## 3. 再現の境界

### 確認済みの体験を参考にする

公開ページで説明されている、一筆入力、枝分かれ、学習、表示個体数・速度調整、描き直し、リプレイという体験を参考にします。

### 内部実装は独自設計にする

原作のソースコード、アセット、非公開パラメータにはアクセスしていません。遺伝子形式、Fitness、選択方式、物理設定は公開されていないため、本プロジェクト独自の再現案として設計します。

### 公開前の知的財産チェック

- 出荷時の作品名とロゴは独自のものにする。
- 原作の画像、音、文章、画面配置をコピーしない。
- 「同じアルゴリズム」と断定せず、「公開された体験を参考にした独自実装」と表現する。
- 公開・収益化の前に、類似性と表示上のクレジット方針を人が確認する。

## 4. 成功条件

### 技術的成功

M7時点の達成状況を併記します。

- 固定骨格の32個体を同条件で評価し、世代交代を継続できる。→ **達成**（[docs/15](15-m2-population-performance.md)）
- 同一Seed・同一ブラウザ・同一バージョンで、許容誤差内の再試行結果を得られる。→ **達成**（同一環境では完全一致。ブラウザ間は未確認）
- 進化を切った対照群より、進化を有効にした群のFitness中央値が明確に改善する。→ **達成**（5 Seedで 17.46 vs 4.17、[docs/16](16-m3-evolution-validation.md) §11）
- 一筆から生成されたBody／Jointが、NaN、無限ループ、即時爆発を起こさず評価を完走する。→ **達成**（[docs/17](17-m4-stroke-input-validation.md)）
- UI描画を減らしても、内部評価結果が変わらない。→ **達成**（表示個体数0／1／8で完全一致）
- 長時間の連続運転で資源が増え続けない。→ **達成**（30分・273周・5,460世代でheap 1.01倍、[docs/20](20-m7-release-readiness.md) §6-2）

### 体験上の成功

**いずれも未確認です。** 体験の統合はM6で終わり、製品画面は公開しましたが、**人による体験確認はまだ行っていません**（[docs/19](19-m6-experience-review.md) §8）。

- 初回利用者が説明を読まずに「描く→学習→観察→描き直す」へ進める。→ **未確認**。製品画面は <https://ayutaz.github.io/one-stroke-evolution-web/> で公開済み
- 数世代のうちに、無秩序な動きから方向性のある動きへ変化したと認識できる。→ **未確認**。人の視認確認が必要（[docs/16](16-m3-evolution-validation.md) §8）
- 奇妙だが有効な移動方法を、過度なペナルティで消さない。→ **設計上は担保**（数値的失敗だけを罰する）。**見た目での確認は未実施**

### 成功とはまだ言えないもの

- 単に関節が動くこと。
- 1個体だけが偶然前へ飛ぶこと。
- 高速化スライダーが存在するだけで、実時間が短縮されていないこと。
- 開発PCだけで動作し、長時間試験や世代切替で資源が増え続けること。
