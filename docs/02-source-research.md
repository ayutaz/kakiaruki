# 原作および関連事例の調査

## 1. 公開情報から確認できた原作仕様

2026-09-14に確認したunityroomの『一筆進化』公開ページには、次が明記されています。

| 項目 | 状態 | 公開情報 |
|---|---|---|
| 入力 | **確認済み** | マウス左ボタンを押したまま一筆で生物を描く |
| 枝分かれ | **確認済み** | 線をなぞって戻ることで枝分かれを作る |
| 修正 | **確認済み** | 「枝を戻す」、Ctrl+Z、Backspace、全描き直し |
| 学習対象 | **確認済み** | 関節の動かし方を少しずつ変える |
| 探索目的 | **確認済み** | より先へ進める動きを探す |
| 許容形状 | **確認済み** | 人型、輪、その他の自由な形 |
| 発現する動き | **確認済み** | 歩行、跳躍、転がりなど |
| 学習操作 | **確認済み** | 「学習開始」で自動学習 |
| 調整 | **確認済み** | 表示個体数と学習速度のスライダー |
| リプレイ | **確認済み** | 成功した動きを観察できる |
| エンジン | **確認済み** | Godot |

この説明から、「プレイヤーが形を作り、探索アルゴリズムが関節制御を変える」という責務分離までは確認できます。

## 2. 公開情報だけでは分からないこと

次は原作の内部仕様として確認できません。

- 遺伝的アルゴリズムか、それ以外の進化戦略かの明示。
- 遺伝子の個数・意味・範囲。
- 関節が角度目標、速度目標、トルクのどれで制御されるか。
- 個体数、Elite数、選択方式、交叉方式、突然変異率。
- 1エピソードの長さ、物理Hz、サブステップ数。
- Fitnessの正確な式。
- 形状簡略化、枝検出、自己交差、閉ループのアルゴリズム。
- 個体を同時に物理計算しているか、順番に評価しているか。

したがって、本プロジェクトのGA・Fitness・グラフ変換設計はすべて **再現のための提案**であり、原作実装の説明ではありません。

## 3. 作者の前作から確認できる関連性

同じ作者の『歩行進化論』は、公開ページ上で遺伝的アルゴリズムを使い、プレイヤーが設計した構造体に歩行を獲得させるシミュレーターだと説明されています。作者は負荷に応じて個体数100から50程度へ下げる案にも言及しています。

作者サイトの制作コメントには、前作の初期案として「プレイヤーがイラストを描き、それを動かす」案が存在し、最終的にはボーン設定を採用したとあります。これにより、『一筆進化』と前作の間に体験上の連続性があることは確認できます。

ただし、前作と新作が同一コード、同一GA、同一Fitnessを共有している証拠にはなりません。

## 4. 合理的な再現モデル

### 推定する処理フロー

```text
一筆入力
  -> 点列の正規化
  -> Node/Edgeグラフ
  -> カプセルBodyと回転Joint
  -> 同じ形の個体を複製
  -> 個体ごとに異なる関節制御パラメータ
  -> 固定時間シミュレーション
  -> 前方移動を中心に評価
  -> 選択・交叉・突然変異
  -> 次世代
```

### このモデルを選ぶ理由

- 公開説明の「関節の動かし方を変える」と整合する。
- 少数の連続値パラメータならブラウザ内で高速に探索できる。
- 物理演算が支配的コストになり、個体数と速度の調整UIが必要になる説明とも整合する。
- ニューラルネットや外部学習環境を導入しなくても成立する。

## 5. 研究上の位置づけ

Karl Simsの1994年の研究は、仮想生物の形態と制御系を進化させる代表例です。本プロジェクトはそれより狭く、形態をプレイヤーが固定し、コントローラだけを探索対象にします。

```text
Karl Sims: 形態 + 制御を進化
本プロジェクト: 形態はプレイヤー、制御だけを進化
```

この縮小により、探索空間を抑え、短時間で見た目の変化を楽しめるゲーム体験へ寄せます。

## 6. 調査結果の要約

- **確認済み**: Webで必要となる入力・物理・関節・UIの要素は既知の技術で構成できる。
- **確認済み**: Phaser Box2Dには回転関節、角度制限、モーター速度、最大モータートルク、カプセル形状がある。
- **推定**: 周期関数とGAの組み合わせが、公開されている体験を低コストで再現する最小モデルになる。
- **未確認**: 原作と同等の自由入力、安定性、学習速度、面白さを得られるかはPoCが必要。
