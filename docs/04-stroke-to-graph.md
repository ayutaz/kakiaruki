## 1. この機能が最大の実装難所

GAより難しいのは、どのような描線でも有限で安定した物理構造へ変換することです。生のPointer点をすべてBodyにすると、数百の短い骨と関節ができ、物理が不安定になります。

目標は次の変換です。

```text
Raw Stroke
  -> 正規化された点列
  -> 位相を保つStrokeGraph
  -> 制約済みCreatureGraph
  -> Body / Joint記述
```

## 2. データモデル案

```text
StrokePoint
  x, y, time, pressure?

GraphNode
  id, position, kind

GraphEdge
  id, nodeA, nodeB, polyline, length

CreatureGraph
  nodes[], edges[], rootNodeId, metadata
```

重要な不変条件は次です。

- Node IDとEdge IDは一意。
- Edgeの両端Nodeが必ず存在する。
- 自己ループEdgeは、明示的に許可するまでは作らない。
- Edge長は最小値以上、最大値以下。
- Node次数、Edge数、総延長に上限がある。
- すべての座標は有限値で、キャンバス内へ正規化される。
- MVPではグラフが1つの連結成分である。

## 3. 推奨パイプライン

### Step 1: 入力取得

- `pointerdown`でStrokeを開始する。
- `pointermove`で、前回点から最小距離以上動いた場合だけ記録する。
- `pointerup`またはキャンセルで確定する。
- Pointer captureを使い、キャンバス外へ出ても終了状態を失わない。
- 点数、描画時間、キャンバス外座標に上限を設ける。

### Step 2: 正規化と等間隔再サンプリング

デバイスごとにPointerイベント密度が異なるため、一定距離間隔へ再サンプリングします。ここでは形状を過度に単純化せず、戻り線や交差の情報を残します。

### Step 3: 位相イベントの検出

次を先に検出します。

- 既存Node付近への再接近。
- 既存Edge付近を逆方向になぞる「戻り」。
- 既存Edgeとの自己交差。
- 一定角度以上の折れ曲がり。
- 始点付近へ戻る閉路候補。

**RDP簡略化を全点列へ先に適用しない**ことが重要です。全体を先に簡略化すると、枝を作るための戻り線や近接イベントを消すおそれがあります。位相を分割した後、各Edgeの内部形状へ局所的に簡略化を適用します。

### Step 4: NodeとEdgeへの分割

始点、終点、戻り点、分岐点、採用する交点をNodeとし、その間をEdgeにします。近すぎるNodeは距離閾値で統合しますが、統合後にEdgeがゼロ長にならないことを再検証します。

### Step 5: 物理用の制約

M4で実装した値です。ワールド短辺は6 mに対応させています。骨数上限は実際に描いた後、2026-09-14 に 10 → 14 本へ再調整しました（[D-010](09-risks-open-questions-and-decisions.md#d-010-一筆の骨数上限を14本にする)）。

| 制約 | 初期提案 | M4の実装値 |
|---|---:|---:|
| 最大Edge数 | 16 | **20**（当初10 → D-010で14 → D-011で20） |
| 戻りとみなす距離 | - | **0.22 m**（M5） |
| 戻りと認める最小の長さ | - | **0.5 m**（M5） |
| 戻り判定で除く直前の点数 | - | **4点＝0.48 m**（M5） |
| 粗くできる骨長の上限 | - | **2 m**（D-011） |
| Nodeの最大次数 | 4 | 4（M4は鎖状のみなので最大2） |
| 最小骨長 | 画面短辺の2% | **0.35 m**（短辺6 mの約5.8%） |
| 最大骨長 | 画面短辺の20% | **1.2 m**（短辺6 mの20%） |
| 最大総延長 | 画面短辺の150% | 粗くした骨長 × 最大Edge数 = 40 m |
| カプセル半径 | 骨長と独立した範囲で固定または段階選択 | **0.11 m 固定**。段階選択は未実装 |
| 等間隔re-sampling幅 | - | 0.12 m |
| 折れ曲がり判定 | - | 0.5 rad |
| 区間内RDPの許容誤差 | - | 0.08 m |
| 閉ループ判定距離 | - | 0.35 m |

最小骨長を短辺の2%（0.12 m）ではなく0.35 mにしたのは、0.12 mの骨が半径0.11 mのカプセルとほぼ同じ大きさになり、物理的に意味のある骨にならないためです。

長すぎるEdgeは等分し、短すぎるEdgeは中間節点を落として隣接Edgeへ統合します。上限を超えた場合は、黙って別形状へ変えず、どの制約に触れたかを理由付きで返します。

## 4. 枝分かれの扱い

原作では戻るようになぞることで枝を作れます。MVPでは次の明示的な規則を提案します。

1. 現在点が既存Edgeの許容帯へ入る。
2. 数サンプルにわたって既存Edgeと逆向きに進む。
3. 既存NodeまたはEdge上の投影点へ吸着する。
4. そこから別方向へ離れた時点を分岐開始とする。

単なる線の近接を分岐と誤認しないため、距離だけでなく進行方向と継続サンプル数を使います。「枝を戻す」はグラフ確定後のEdge単位Undoとして実装すると、Pointer点単位Undoより理解しやすくなります。

## 5. 自己交差と閉ループ

### MVPでの提案

- 戻り線による枝分かれは対応する。
- 任意の交差は見た目だけ交差させるか、Node化するかをUI仕様として明示する。
- 始点と終点が近い場合の単純閉ループは、P4以降の安定性試験後に有効化する。
- 多重ループ、非常に短い閉路、重複Edgeは拒否または修正候補として表示する。

閉ループは物理ソルバに循環拘束を作るため、木構造より不安定になりやすいです。カプセル長、質量比、サブステップ数、角度limitを組み合わせた試験が必要です。

### 戻り線による枝分かれ（M5、確認済み）

一筆が往路を逆向きになぞって戻った区間を切り出し、戻り終わった位置を分岐点にします。判定は3条件すべてを満たしたときだけです。

1. `snapDistance`（0.22 m）以内に往路の点がある。
2. その点との進行方向の内積が負（＝逆向き）。
3. その状態が `minRetraceLength`（0.5 m）以上続く。

「近いだけの線」「同じ向きに並走する線」「鋭い折り返し」は、いずれか1つを満たさないため枝になりません。区別の実例は [M5検証結果](18-m5-branching-validation.md) §5 にあります。

枝は分岐位置に最も近い既存Nodeへ繋ぎます。近いNodeが無ければ、最も近いEdgeをその位置で分割して分岐Nodeを作ります。

### 交差判定の実装上の注意（M4、確認済み）

線分の交差は外積の符号で判定しますが、**外積がちょうど0になる「一直線上」を片側として数えてはいけません**。re-sampling した点列では、まっすぐな部分の外積が 0 と ±1e-17 に割れます。`(d1 > 0) !== (d2 > 0)` のような書き方では、これを符号違い＝交差と読みます。

実測では、**自己交差しえない線（xが単調増加）の 8.1% を誤って拒否**していました。両端が厳密に反対側にある場合だけを交差とし、丸め誤差用に `COLLINEAR_EPSILON = 1e-9` を置いて解決しています。詳細は [M4検証結果](17-m4-stroke-input-validation.md) §11「原因3」。

**M5からは、点列ではなく組み立てた骨どうしで交差を判定します。** 戻り線は同じ線を重ねてなぞるため、点列のまま見ると re-sampling のずれで必ず交差します（人型の一筆が実際に拒否されました）。

## 6. Graphから物理構造への変換

- Edgeごとに、その両端を中心線とするカプセルBodyを作る。
- Edgeの中点をBody位置、方向をBody角度、長さをカプセル中心線長とする。
- 共有Nodeに接続するBody同士をRevolute Jointで結ぶ。
- 接続Body間の衝突は原則無効化する。
- 次数3以上のNodeでは、基準Bodyを1つ選び、残りを基準Bodyへ接続する。
- rootは重心に近いNodeまたは最長Edge周辺から決め、ID順に依存しない安定した規則にする。

## 7. 受入試験用の代表形状

実測結果を併記します（画面640×480、ワールド短辺6 m）。枝分かれを含む結果は [M5検証結果](18-m5-branching-validation.md) §6 にあります。

| 形状 | 期待 | M4の結果 |
|---|---|---|
| 直線 | 1 Body、Jointなし | **5 Body / 4 Joint**。最大骨長1.2 mで分割されるため。期待欄は短い線を前提にした記述 |
| L字 | 2 Body、1 Joint | **6 Body / 5 Joint**（同上）。**鋭い折れ曲がりは1箇所だけ**保持される |
| 人型相当の木 | 複数枝、単一連結成分 | **未対応（M5）** |
| 戻り線を含むY字 | 分岐Nodeの次数3 | **未対応（M5）** |
| 単純な輪 | P4までは明示的に保留または安全に拒否 | **拒否**（`closed-loop`、理由と直し方を返す） |
| 小さなジグザグ | 上限内へ簡略化される | **8 Body / 7 Joint**、鋭い折れ曲がり3箇所 |
| 同一点を連打 | ゼロ長Edgeを作らない | **拒否**（`stroke-too-short`）。ゼロ長Edgeは生成されない |
| 極端な長線 | 上限で分割または拒否理由を返す | 上限内なら分割、超えたら `too-many-edges` を返す |
| NaN相当の不正入力 | 例外で全体を壊さずValidation error | `StrokeRecorder` が非有限・範囲外の点を記録しない。全体を壊さない |
| 緩い弧 | （新規） | **6 Body / 5 Joint**。折れ曲がりを作らず弧に沿う |
| 終端に0.2 mの突起 | （新規） | 突起を隣へ統合。最小骨長未満のEdgeを作らない |

「直線 → 1 Body」という当初の期待は、物理制約（最大骨長）と両立しません。長い直線が複数の骨に分かれるのは仕様どおりです。

### 長い線は拒否せず、骨を粗くして収める（D-011、確認済み 2026-09-14）

骨数が上限を超えたとき、**長いというだけで拒否しません**。骨の上限長と簡略化の許容誤差だけを粗くして組み直し、描いた形のまま収めます。

**最小骨長は粗くしません。** 上げると短い骨が次々に統合され、描いた形そのものが消えるためです（実測で総延長が 22.8 m → 1.4 m まで潰れました）。

粗くできる骨長は 2 m までです。それでも収まらない線だけを、理由付きで拒否します。

| 描線の長さ | 骨数 | 骨の総延長（保存率） | 1本の長さ |
|---:|---:|---|---|
| 17.0 m | 15 | 16.8 m（98%） | 0.90〜1.19 m |
| 21.5 m | 19 | 21.4 m（99%） | 1.12〜1.14 m |
| 25.8 m | 14 | 25.5 m（99%） | 1.69〜1.86 m |
| 45.0 m | - | - | 拒否（骨を太くしても26本必要） |

### 実際に描ける長さ（640×420のキャンバス、確認済み 2026-09-14）

骨数上限14本は「14 × 1.2 m = 16.8 m」ですが、`splitLongEdges` は長いEdgeを等分するため、1本あたりは平均 0.9〜1.0 m に落ち着きます。実用上の上限は**描線の長さで約 930 px（キャンバス幅の約1.5倍）**です。

| 描いた線 | 長さ | 骨数 | 結果 |
|---|---:|---:|---|
| 対角1本 | 655 px | 8 | OK |
| 波2山 | 930 px | 12 | OK |
| 波3山 | 1,147 px | 16 | 拒否（14本超） |
| 波4山 | 1,363 px | 19 | 拒否（14本超） |
